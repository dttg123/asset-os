# Asset OS 30년 수동 QA 결과 — 전체 통과 아님

검사일: 2026-09-19~20. 운영 원장 변경 없음. 빈 QA에서 화면 폼으로 입력했다. 저장소 직접 주입과 35년 생성 자료는 사용하지 않았다. 2031~2060년은 가상 사용기간이며 미래 제도나 미래 수입의 예측이 아니다.

## 검사 범위와 한계

30년 월별 기록 입력과 아래 생애주기 검사는 완료했다. **모든 세부 버튼 2회 이상이라는 전체 조건은 아직 완료하지 못했다.** 주요 11개 하위 탭은 2회씩 전환했다. 미지원 기능은 통과로 간주하지 않았다. 클라우드 브라우저의 데스크톱 화면을 검사했으며 모바일 실기기 검사로 대체할 수 없다. KIS 실계좌 연결과 ChatGPT 외부 전송은 실행하지 않았다.

## 필수 수정 1: 수동 연금 평가액과 통합 자산 불일치

새 빈 QA에서 연금계좌를 만들고 거래를 직접 기록하면 재현된다.

- 연금 화면의 전체 평가액: **108,022,400원**.
- 통합의 연금저축+IRP: **108,000,000원**, 납입액만 반영.
- 누락 차이: **22,400원**. 수령액 7,400원 + 실현차익 2,000원 + 잔여 보유분 평가이익 13,000원.
- 최종 통합 표시 순금융자산: **799,589,610원**.
- 같은 시점 현금·ISA·연금 평가액을 합친 값: **799,612,010원**.
- 원인: `integratedFinancialModel()`이 `moduleVerification.pension/irp`가 false이면 수동 연금 거래 평가액 대신 연결 납입 합계를 선택한다. 백업에서 두 플래그가 false임을 확인했다.
- 개선: 사용 가능한 수동 원장 평가액과 증권사 잔고의 우선순위를 명시하고, 자료 확인 상태를 금액 집계 가능 여부와 분리해야 한다. 홈·통합·연금·AI가 같은 자산 기준을 사용해야 한다.
- 이 조건의 QA 재현이며 운영 사용자 원장에도 동일 문제가 발생한다고 확인한 것은 아니다.

## 필수 수정 2: ISA 생애주기 실행 기능

신규 계좌 등록과 36개월 납입은 성공했고 계좌 현금 1,080만원에 반영됐다. 하지만 운영 계좌의 만기 연장·해지·연금 전환을 실행하는 화면이 없다. 세금·만기 화면에는 예상 세금과 전환 미리보기만 있다. 계좌 선택은 현재·이전 회차 조회 중심이다. 코드상 종료된 ISA 예시 자료 및 만기 결과 표시와 실제 신규 종료 처리 흐름을 구분해야 한다.

따라서 30년 여러 ISA 회차의 만기→정산→재가입 연속 운용은 **미지원으로 막힘**이다. 생성 자료에 과거 회차가 존재하는 것은 이 기능의 검증 증거가 아니다.

필요한 범위: 실제 종료일·원금·손익·세금·수령액 기록, 현금 또는 연금으로 1회 연결, 연장 이력, 후속 회차 생성, 과거 회차 읽기 전용 보존. 실제 금융회사 거래를 실행하는 기능이 아니라 사용자 거래 결과를 기록하는 기능이다.

## 필수 수정 3: 환불·부분취소

통합 지출 상세는 수정·삭제만 제공한다. 입력 유형에도 환불이 없고 음수 지출은 입력 단계에서 차단된다. 원거래를 보존하면서 환불 날짜와 금액을 연결하는 처리 경로가 없다.

필요한 범위: 전액·부분 환불, 여러 번 환불한 누계가 원금 초과하지 않도록 검증, 다른 달 환불, 실제 현금 복귀, 소비 통계 기준 명시. 원거래 금액을 덮어쓰는 것으로 대체하면 이력을 잃는다.

## 필수 수정 4: 보험 추정액을 실제 납부로 표시

월 1만원, 2031-01~2060-12 보험을 새로 등록했다. 실제 납부 기록이 0건인데 보험 상세에 **납입 완료 3,600,000원**이 표시됐다. 계약 기간×보험료 추정액이다.

실제 납부 누계와 계약상 예상 누계를 분리해야 한다. 실제 기록이 없으면 납입 완료로 단정하지 않아야 한다. 계약을 두 차례 같은 값으로 저장해도 연결 일정은 1건이었고, 두 달 납부 후 계약 종료 시 과거 납부 2건은 보존됐다.

## 보완: 계좌별 거래와 CSV의 납입 포함 범위

1,483건 시점에 실제 CSV ZIP을 내려받아 확인했다.

- 통합거래.csv: 1,483행.
- 월별요약.csv: 360행.
- ISA거래.csv: 0행.
- 연금거래.csv: 0행.

이 시점의 ISA·연금 납입은 전부 통합 원장에 저장돼 계좌별 CSV에는 포함되지 않았다. 이후 매수·수령 등 연금 거래 12건은 연금 화면에 표시됐다. 자료가 소실된 것은 아니지만 계좌별 내보내기가 전체 계좌 이력이라는 기대를 충족하지 못한다. 원장 중복 저장 없이 연결 납입도 계좌별 조회·내보내기에 포함하고 출처와 기록ID를 유지하는 방식을 권장한다.

## 통과한 검사

- 빈 QA 재접속 보존: 이전에는 reset 후 reload 시 7,740건 자동 생성 자료로 교체됐다. 자동 생성 분기를 제거해 수정·배포했다. 명시적인 생성 버튼은 유지했다.
- QA 수정 후 Node 전체 자동검사: 66/66 통과. 자동검사가 아래 모든 UI 조건을 대신하지는 않는다.
- 급여·생활비 720건: 10년·20년·30년 지점에서 재접속·누적현금 검산. 30년 합계 804,600,000원 일치.
- 연금저축·IRP 각 360개월 납입 후 재접속: 계좌별 납입 합계와 통합 현금 감소 일치. 거래 수익 발생 전 현금 685,800,000원 + 투자자산 118,800,000원 = 804,600,000원.
- 예금: 현금 출처를 선택해 100만원 가입. 만기 수령 1,029,610원 입력 시 원금 회수 100만원과 이자 29,610원 분리. 잔액 0원·종료 확인.
- 대출: 시작 500만원, 일부 상환 200만원, 이자 2만원, 남은 300만원 완납. 잔액 0원·완납 확인.
- ZIP 백업·복원 각각 두 차례 실행. 복원 후 재접속에서 당시 1,483건 유지. 최종 1,497건 상태는 별도 백업으로 보관.
- 연금 직접 입력의 매수·매도·배당·분배금·이자·기타 권리를 두 계좌에서 각각 저장. 거래 12건과 누적 현금수익 7,400원 표시 일치.
- 주요 하위 탭 11개를 두 차례 전환. 4개 테마색 각 두 차례 선택, 다크모드·진동 전환.
- 미래연금 목표 65→70→65 변경. 70세 예상자산·월연금 카드 각각 높이 78px 확인.
- AI 추가금 100만원 매수 판단, 0원 리밸런싱 자료 생성 및 입력 수정. 외부 전송은 미실행.
- QA 가상 2061년 제도(실제 정책 아님)를 별도 버전 저장. QA 현재일 2060-12-31에서 적용을 두 번 시도해 모두 시행일 이전 차단. 기존 제도와 원장은 유지.

## 화면 다이어트·정확성 개선

1. 날짜 선택을 이전/다음 달 화살표만으로 제한하지 말고 연·월 바로 선택 제공.
2. 과거 월 현금흐름과 현재 자산 총액의 기준 시점을 짧게 명시.
3. 대출 완납 상세의 `실제 수령/정산 0원`은 완납 원금·이자·수수료와 맞는 문구로 수정.
4. 백업 위치 선택 제한 시 기술적인 `showSaveFilePicker` 오류 전문을 기본 안내에서 숨기고 저장 결과·위치만 안내. 이 브라우저에서는 기본 다운로드로 ZIP이 실제 생성됐다.
5. 긴 조회·계산 설명은 접기 안에 유지. 신규 메인 그래프·뉴스·상품추천·복잡한 예산 기능 추가는 권장하지 않는다.
6. 빠른 연속 조작 중 마우스 클릭이 실행되지 않은 사례가 있었으며 키보드 폼 제출은 안정적이었다. 브라우저 확장 메타데이터 오류도 관측돼 앱 단독 결함으로 확정하지 않았다. 실제 모바일 터치 재현이 필요하다.

## 외부 비교에서 반영할 점

[편한가계부](https://ko.realbyteapps.com/)는 기간 조회·필터·저축/대출 관리를 제공한다. [뱅크샐러드 고객센터](https://help.banksalad.com/1006)는 거래가 안 보일 때 연결·숨김·거래수단 선택을 확인하도록 안내한다. Asset OS에도 거래 출처, 범위, 마지막 조회 시점을 짧게 보여주는 편이 도움이 된다.

[오빠두 자산관리 구글 시트의 사용자 의견](https://www.oppadu.com/resources/구글-자산-관리/)에는 계좌가 다른 같은 종목의 합산과 환율 기준에 관한 구체적 질문이 있다. [2024년 뱅크샐러드 사용 후기](https://rein.kr/posts/2024-09-30-bank-salad-재시도/)도 참고했다. 이는 특정 시점의 사용자 경험이며 현재 해당 서비스 전체의 결함으로 일반화하지 않는다. 비교 결론은 새 기능 수보다 계좌별 분리, 내부이체, 원거래 이력, 합계의 설명 가능성을 우선하는 것이다.

## 아직 통과 처리할 수 없는 항목

- 모든 세부 버튼 최소 2회 및 전체 오류 분기 전수검사.
- ISA 만기 연장·해지·전환·재가입 연속 회차: 실행 흐름 미지원.
- 환불·부분취소·교차월 환불: 기능 미지원.
- 모든 예적금 유형·중도해지 손실·대출 수수료·금리 변경 조합.
- 연금 계좌 이전·보관·재개 전체 조합과 모든 제도 변경 경계.
- 실제 KIS 지급유형 코드 분류 및 동기화, 실제 ChatGPT 공유, 모바일 실기기.

우선순위는 연금·통합 금액 일치 → ISA 회차 종료/연장 → 환불·부분취소 → 보험 실제/추정 구분 → 계좌별 조회·CSV 완결성이다. 현재는 30년 종합 운용 최종 통과나 운영 배포 완료 판정을 내릴 수 없다. 이번 운영 코드 변경은 QA 보존 수정과 수동 QA 진입점에 한정하며 위 핵심 금융 로직은 아직 변경하지 않았다.
