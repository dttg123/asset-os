ASSET OS v0.6.1 현재 인수인계
최종 갱신: 2026-09-06

[v0.6.1 금액·문구 정리]
- 홈의 이번 달 납입액을 연금저축·IRP만이 아니라 ISA까지 포함한 합계로 교정하고 상세 내역과 일치시킨다.
- 부채가 줄면 `부채 감소`, 늘면 `부채 증가`, 변동이 없으면 `부채 변동`으로 방향과 금액을 명확히 표시한다.
- 통합 화면의 자산·부채 명칭과 데이터 기준 문구를 사용자 표현으로 짧게 정리한다.
- 개인연금의 한투·과거자료 설명에서 개발자식 표현과 중복 문구를 제거하되 중복합산 방지 안내는 유지한다.
- QA ISA 이름은 실제 납입 합계를 표시하며 `1억원 성장`처럼 현재값으로 오해할 표현을 사용하지 않는다.
- 운영 앱·QA·정적자산·서비스워커 버전을 v0.6.1로 함께 올리고 저장 키와 schema 20은 유지한다.
- 자동검사 31개와 35년·7,756건 QA 금액 검산을 모두 통과한다.

[v0.6.0 장기 거래 검색]
- 통합 거래에서 날짜·금액·분류·계좌·메모를 기준으로 전체 기간을 검색한다.
- 개인연금·IRP 거래에서 날짜·금액·종목·계좌·메모를 기준으로 직접 입력·한투 조회·과거 확정자료를 함께 검색한다.
- 검색어는 화면 세션에만 유지하며 원장·설정·운영 저장 키와 데이터 구조는 변경하지 않는다.
- 검색 결과는 50건 또는 20건 단위로 나눠 표시해 35년 장부에서도 화면 부하를 제한한다.
- 운영 앱·QA·정적자산·서비스워커 버전을 v0.6.0으로 함께 올린다.

[v0.5.1 클라우드 재진입 수정]
- 실계좌 연금저축·IRP의 현재 잔고·누락 체결 조회와 Supabase 저장은 실제 브라우저에서 성공했다.
- KIS 저장 뒤 새로고침하면 같은 원장을 JSON 객체 키 순서 차이로 충돌 오판해 인증 게이트가 잠기는 현상을 실제 재현했다.
- 클라우드 원장 비교를 객체 키 순서와 무관한 정규 순서 직렬화로 바꿨다. 배열 순서와 실제 값 차이는 계속 충돌로 판정한다.
- KIS 저장 뒤 Supabase JSONB의 중첩 키 순서가 달라진 상태로 새로고침하는 회귀시험을 추가했다.
- 실제 충돌·빈 클라우드 보호·잘못된 클라우드 형식·DB 설정·동기화 오류를 일반 네트워크 오류와 구분해 표시한다.
- 운영 저장 키와 QA 저장 키는 변경하지 않고 앱·QA·정적자산·서비스워커 버전만 v0.5.1로 함께 올린다.

[v0.5.0 배포 준비]
- 운영 저장 키 asset-os-v1.9.45-live는 유지하고, v0.5.0 QA는 기존 전용 키 asset-os-qa-v0.5를 재사용해 QA 버전별 누적을 막는다.
- 운영/QA 백업 파일명·폴더 핸들·IndexedDB를 분리하고 교차 복원을 차단한다.
- 손상 데이터, 복원, 클라우드 교체는 검증된 복구 사본 없이는 원본을 덮어쓰지 않는다.
- 특정 ID의 통합 거래·연금 납입 기록을 정규화 중 자동 삭제하던 코드를 제거했다.
- 종료 ISA도 거래원장을 감사 재생하고, 잔고 대조·연금 거래 삭제는 실패 시 원자적으로 취소한다.
- KIS 오래된 응답 역전, 주문 커서 오염, 권위 있는 0원 잔고, 부분체결 잔량을 교정했다.
- 앱/정적자산/서비스워커/QA 표시 버전을 v0.5.0으로 통일하고 과거 캐시 목록을 단일 셸로 축소했다.
- v0.5.0 정적자산 캐시 키도 0.5.0으로 통일했다.
- 35년 QA 상태는 파생·기본 필드를 저장 시 생략해 약 1.36MB로 줄이고, 로드 시 정규화로 복원한다.
- QA 데이터셋 버전이 앱과 다르면 QA 저장소만 자동 재생성해 구버전 가상 오류가 남지 않게 한다.
- 수동 ISA·연금 스냅샷은 자동 저장이 덮어쓰지 않으며, 초기자료 병합 전 복구 사본을 재읽어 검증한다.
- 미래연금은 이번 달 실제 납입액이 아니라 반복 납입 계획을 사용하고, 예·적금 이자는 실제 납입·출금 날짜별로 계산한다.
- 정상적인 한투 기타자산은 AI 공유 경고로 전달하되 음수 구성 불일치는 차단한다.
- 동일 조건의 정상 ISA 분할체결은 순번별로 보존하고, 연속 탭은 저장 버튼 잠금으로 한 번만 반영한다.
- ISA 만기 실제값은 음수·NaN·정산액 초과를 저장 전에 차단한다.
- 자동 테스트 29개와 35년·7,756건 QA 자료 검산을 통과한 뒤 main 배포한다.

[절대 원칙]
- 기존 사용자 원장과 설정을 삭제하거나 초기화해 오류를 숨기지 않는다.
- KIS는 조회 전용이다. 체결·권리를 납입·매매·배당 원장에 자동 합산하지 않는다.
- 앱키·시크릿·계좌번호·토큰은 프런트 코드, 앱 상태, 백업에 저장하지 않는다.
- 실제 실행하지 않은 항목을 PASS로 적지 않는다.
- 수정할 때마다 이 파일에서 끝난 내용과 남은 내용을 최신 상태로 교체한다.

[이번 구현]
- 한국투자 연결 화면에 연금저축·IRP별 ‘처음 거래한 날짜’와 ‘과거 전체 체결·권리 가져오기’를 추가했다.
- 체결은 31일 단위, 권리는 365일 단위로 처음 거래일부터 오늘까지 순차 조회한다.
- 각 구간 응답을 즉시 기존 state.brokerKis에 중복 제거 저장한다.
- 계좌·시작일·완료 구간·오류·완료일을 state.brokerKis.history에 저장한다.
- 중간 실패 시 상태를 paused로 저장하며 다음 실행은 마지막 완료일 다음 날부터 재개한다.
- 시작일이나 연결 계좌를 바꾸면 이전 진행 커서를 재사용하지 않는다.
- 잔고 스냅샷 120개 제한을 제거해 앱이 실제로 수집한 일별 잔고를 계속 보존한다.
- 과거 체결, 권리, 진행상태, 잔고는 localStorage·Supabase 상태·ZIP 백업에 함께 포함된다.
- KIS 저장 스키마를 version 2로 올렸고 기존 version 1 데이터는 normalizeBrokerKis로 그대로 승계한다.
- broker-kis.js, ui-settings.js, boot.js 캐시 버전을 v0.4.2로 갱신했다.
- 개인연금 납입·공제 화면에 ‘월 납입 기록 맞추기’를 추가했다. 연도·기준월·납입일·월 금액·실제 납입월·연결 계좌를 검토한 뒤 원장과 반복 일정을 함께 저장한다.
- 기존 수동 원장은 보존하고 이 기능이 만든 같은 연도 기록만 멱등 교체한다. 기존 수동 금액이 설정액보다 크면 저장 전 충돌로 차단한다.
- 미래월 완료 기록을 차단하고, 사용자가 확인한 첫 납입일보다 늦게 잡힌 로컬 계좌 개설일만 그 날짜로 앞당긴다.
- 앱 밖 계좌의 externalAssetIn은 저축·투자 합계에는 포함하되 생활현금에서는 차감하지 않도록 월 요약 계산을 수정했다.
- 변경 모듈과 스타일 캐시를 v0.4.4로 갱신했다.
