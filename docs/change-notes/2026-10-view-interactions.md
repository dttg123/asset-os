# 조회 동작과 화면 전환 최소 수정

메뉴, 계좌 선택, 소비 필터, ISA·연금 구성 및 배당 조회에서 전체 원장 저장을 호출해 저장 상태 표시와 입력 잠금이 발생했다. 조회 핸들러만 전체 저장에서 분리한다. 금융 계산, 원장 구조, persist의 중복 제출 보호·잠금·실패 롤백은 유지한다.

조회 설정은 기존 settings 필드를 사용하되 허용 목록만 탭의 sessionStorage에 기억한다. 새로고침 때 원장에 저장된 설정이 당시 기준값과 같은 항목만 복구한다. 이후 실제 저장·복원으로 바뀐 설정을 오래된 조회값으로 덮지 않는다. 잘못된 값이나 세션 저장 실패는 조회를 차단하지 않는다. 기기 간 동기화 대상은 아니다.

전체 render마다 반복되는 pageReveal 페이드를 제거한다. 분석 시트의 배경은 흐림 필터 없이 밝게 조정하고, 기존 시트 이동과 같은 시간에 서서히 표시한다. 네이티브 터치 하이라이트를 제거하되 키보드 focus-visible과 선택 표시는 유지한다. 시트의 뒤로가기, 입력 중 닫기 확인, 배경 차단 로직은 변경하지 않는다.

QA는 조회 시 DB commit·revision·저장 잠금·금융 컬렉션을 계측하고, 실제 기록 저장의 실패 복구·중복 입력·ZIP 백업·복원 및 장기 금융 계산을 기존 테스트로 검증한다. 모바일 검증은 브라우저 뷰포트·터치 에뮬레이션이며 실기기의 프레임 속도 보증은 아니다.

## 재현 및 검증

- 수정 전 조회 시나리오: DB commit 8회, 저장 잠금 8회, revision 증가. 금융 컬렉션은 동일했다.
- 수정 후 동일 시나리오: commit 0회, 저장 잠금 0회, revision 동일, 금융 컬렉션 동일. 새로고침 후 조회 선택 유지.
- Node 전체 246/246 통과(30·35년 QA 포함), QA FAST 모든 게이트 통과, npm audit 취약점 0건.
- 보관된 실제 기록 사본(revision 91)을 QA에만 복사해 320·412·768px와 두 테마 검증: 금융 컬렉션·DB revision 보존, 외부 요청 0회, 운영 쓰기 0회. 신규 운영 조회 결과라는 의미는 아니다.
- 기존 액션 디자인 테스트의 pageReveal 기대값은 반복 페이드 제거 요구에 맞춰 none으로 변경한다. 금융 보존·입력 보호 검증은 유지한다.
